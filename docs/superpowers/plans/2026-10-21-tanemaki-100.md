# たねまき 100ステージ化・筆算・あまりのあるわり算 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 「たねまき」を5グループ・20ステージから25グループ・100ステージへ広げる。筆算（縦書き）の表示と、あまりのあるわり算（商とあまりを別々に答える、降らない専用の遊び）を新しく作る。

**Architecture:** 筆算は `SeedProblem` に任意の `display`（縦書きの情報）を足すだけで、既存の種が降る仕組み・答えの比べ方（数字1つ）はそのまま使う。あまりのあるわり算は、既存の `SeedRun`/`tapRun`（数字1つの比較）を変えず、**完全に別の小さな状態機械**（`remainder-division.ts`）と**別の画面**（`RemainderDivisionPlayer`）として横に作り、点数・ゲージ・フィーバーだけ既存の `useSpeedPlay`（問題の形に依存しない）を再利用する。データ（25グループ100ステージ）は、既存の `ADD_STAGE_SPECS`・`SUB_STAGE_SPECS`・`MUL_STAGE_SPECS`・`DIV_STAGE_SPECS` のルールを番号で再利用する。

**Tech Stack:** Next.js 16 / React 19 / TypeScript / Tailwind v4 / Vitest（`projects/tane/frontend`）。

**Spec:** `company/spra/tane/docs/2026-10-21-tanemaki-100-design.md`

## Global Constraints

- ドキュメント・画面の文字は日本語（子ども向けはひらがな中心）。
- 既存の「たねまき」1〜20ステージ（グループ1〜5）・分野別の「きそ・きほん」・そろばん・フラッシュ・チャレンジの挙動は変えない。全テストが通り続けること。
- 筆算（`display`）は、たしざん・ひきざん・かけざんだけ。わり算の筆算（縦に1桁ずつ引く形）は作らない（設計書2章・3-2）。
- あまりのあるわり算は、**降らない・1問ずつ・2分・間違えたら次へ進む**（虫食いと同じ外側の枠）。`SeedRun`・`tapRun`・`NumericKeypad` の中身・比べ方は変えない（設計書3-2）。
- 2桁×2桁のかけざん筆算は、部分積（一の位・十の位で分けて書く行）を表示しない。答えは最後の数字1つ（設計書5章）。
- 「ふつう・筆算・虫食い」を**同じステージの中で混ぜることはしない**。1ステージ＝1つの出し方（設計書4章 G20の注記）。
- ステージID は `shisoku-21`〜`shisoku-100`。表示番号は既存の `displayNumber`（`SHISOKU_GROUP_SIZE=4` から自動計算）がそのまま使える。`SHISOKU_GROUP_NAMES` を25個に増やす。
- ★の最大5・ロック解除★3は、既存の `maxStars`/`unlockStars`（`stage.kind === "seed"` 判定）がそのまま使える。あまりのあるわり算のステージも `kind: "seed"` のまま（画面だけ分ける）。
- 数値（`fallMs`・`thresholds`・`roundMs`）はすべて初期値。遊んでから直す（既存のコード内コメントと同じ方針）。

## Review Focus

- 筆算の `display` が無いとき、今までどおりの横書きの見た目・動きに戻ること（既存の種が降る・虫食いのテストが壊れない）。
- あまりのあるわり算で、商だけ合っていて、あまりが違うときは不正解になること（部分点を作らない）。
- あまりのあるわり算で、時間切れとHP0が同時でも、記録は1回だけ（既存の `seed-run.ts` と同じ考え方を、新しい状態機械でも守る）。
- 新しい100ステージすべてで、`generateProblems`（既存）または新しい `generateDivModProblem` が実際に問題を作れること（無限ループ・例外にならない）。
- 2桁×2桁の筆算で、桁数が違う数（例：11×19）でも、右そろえの表示が崩れないこと。
- `tane:progress:v1` の互換性：既存の★5のステージが混ざっていても読み込める（`maxStars` は変わらないので、ここは壊れにくいが確認する）。

### Task 2: あまりのあるわり算（ロジック）

**Files:**
- Create: `src/lib/game/remainder-division.ts`、`src/lib/game/remainder-division.test.ts`

**Interfaces:**
- Consumes: `pickNumber`・`NumberPick`（`problem-rules.ts`、既存のまま export 済み）、`INITIAL_HP`・`applyDamage`・`isDefeated`（`hp.ts`、既存）
- Produces:
  - `interface DivModRule { divisor: NumberPick; quotient: NumberPick }`
  - `interface DivModProblem { a: number; b: number; quotient: number; remainder: number }`（`a = b*quotient + remainder`、`remainder` は必ず1以上）
  - `generateDivModProblem(rule: DivModRule, avoid?: { a: number; b: number } | null, rng?: () => number): DivModProblem`（避ける組は最大20回引き直す。避けられなければそのまま返す）
  - `type DivModMode = "minute" | "endless"`、`type DivModStatus = "playing" | "timeup" | "defeated"`
  - `interface DivModRun { mode; status; problem: DivModProblem; hp: number; correct: number; mistakes: number; combo: number; maxCombo: number; playedMs: number }`
  - `createDivModRun(rule: DivModRule, mode: DivModMode, rng?): DivModRun`
  - `stepDivModRun(run: DivModRun, dtMs: number, roundMs: number): DivModRun`（`dtMs` は `MAX_TICK_MS`=100 に切る。`mode==="minute"` かつ `playedMs>=roundMs` で `status:"timeup"`。終わった run は変えない）
  - `answerDivMod(run: DivModRun, quotientInput: number, remainderInput: number, rule: DivModRule, rng?): { run: DivModRun; correct: boolean }`（終わった run には何もしない。正解：`correct+1`・`combo+1`・`maxCombo` 更新・次の問題（直前と同じ a,b は避ける）。不正解：`mistakes+1`・`combo:0`・`hp=applyDamage(hp)`。HPが0なら `status:"defeated"`、そうでなければ次の問題へ進む（虫食いと同じ「間違えても次へ」））

- [ ] **Step 1: Write the failing tests**
  - `generateDivModProblem`：`remainder` が1以上`divisor`未満、`a = b*quotient+remainder`、固定乱数で200回流して`remainder===0`が無い
  - 避ける組：`avoid` と同じ `{a,b}` を極力避ける（既存の `drawSeedProblem` のテストと同じ形。避けられないルールでは止まらない）
  - `stepDivModRun`：`dtMs=5000` でも `playedMs` は100しか進まない（タブ復帰対策）。`mode:"minute"` で `playedMs>=roundMs` になると `timeup`。`mode:"endless"` は時間で終わらない。終わった run に `stepDivModRun` しても変わらない
  - `answerDivMod`：商・あまり両方合えば正解、片方だけ違えば不正解。不正解で `hp` が減り `combo` が0。`hp` が0で `defeated`、それ以降 `answerDivMod` しても変わらない。不正解でも（defeatedでなければ）次の問題が出て、直前と同じ `a,b` が続けて出ない（固定乱数で50回確認）
